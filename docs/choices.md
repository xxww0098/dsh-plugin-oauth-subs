# 对抗审查的设计取舍

本账本记录 2026-09-08 质量审查中请求未逐项指定、但实现必须选择的行为。不是新功能计划，也不是“测试通过所以架构正确”的替代品。置信度表示对维护者会作相同选择的把握。

优先审阅两项：**显式模型选择的标记是全局的**；**账号写回只提供进程内串行保护**。全局模型标记与旧配置恢复属于 needs-user（产品取舍，暂保留兼容方案，不阻塞本轮）；其余已实现项为 sound。未实施的边界与复审修正见末节。

## Needs-user · medium：显式模型选择使用一个全局持久标记

- **时间**：本轮模型选择修复。
- **选择与场景**：用户把 GLM 全关，普通同步和重启都保持关闭。一旦用户在任一家做过有效模型选择，就保存 `selectionExplicit`；此后不再用“全关一定是坏配置”的推测恢复其它家。另一方案是为每一家保存独立的选择标记；本轮没有增加这套状态。
- **未指定处**：旧配置自动恢复与新用户选择如何区分。
- **影响**：旧无标记文件仍按原规则恢复。未来新增的普通模型仍默认开启，900K 仍要主动开启；这个标记不是“永远禁用整家”的开关。
- **判断**：needs-user。暂保留全局方案，优先不擅自改动用户选择；若以后希望独立恢复未操作的厂商，可改为按族记录并将现有 true 迁移为全族已明确。**置信度：medium**。

## Needs-user · medium：旧无标记文件保留兼容恢复

- **时间**：本轮模型选择修复。
- **选择与场景**：旧文件只有禁用的模型列表，没有用户操作标记。同步仍可能把其中全关的一族当成旧故障恢复；它无法知道用户在旧版本是否故意关掉。这不是执行一次就结束的迁移，只有有效用户操作才封住恢复。
- **未指定处**：不能区分的旧配置应自动救援还是一律尊重关闭。
- **影响**：本轮只承诺新版本成功保存后的明确选择不被重开；没有承诺旧版本意图或降级保存后再升级的标记往返。
- **判断**：needs-user。暂保留既有兼容行为；反向方案是关闭自动救援、让用户手动重新开启，未来可逆调整。**置信度：medium**。

## Sound · medium：账号切换只影响后来发起的请求

- **时间**：本轮刷新生命周期修复。
- **选择与场景**：A 的请求已在刷新，用户切到 B。旧请求仍可用刷新后的 A 完成；新请求独立使用 B，A 的结果不会把当前账号切回去。另一方案是切换时取消所有旧请求，会额外中断已接受的工作。
- **未指定处**：切换账号是否意味着取消在途对话。
- **影响**：刷新结果按发起时的登录归属保存，而不是在返回时再读取 active。注销或重新登录导致来源失效时，旧刷新报“会话已变化”，不拿陈旧凭据继续发请求。
- **判断**：sound。保护新选择而不无故丢弃旧请求。**置信度：medium**。

## Sound · medium：凭据写回保护限于同一进程

- **时间**：本轮存储与刷新修复。
- **选择与场景**：聊天与额度同时请求刷新时，读写进入同一文件的串行队列，刷新按登录版本只兑换一次。两个独立 OS 进程同时写同一文件则没有跨进程锁；本轮没有新增锁文件、锁过期或恢复协议。
- **未指定处**：多个进程共享凭据文件时需要什么协调机制。
- **影响**：原子 rename 保证单次文件替换完整；它不等于跨进程事务。后续若支持多进程共同刷新，须单独设计并验证锁与崩溃恢复，不能把当前方案宣传成已解决。
- **判断**：sound。修复本进程真实竞态而不无证据引入跨进程协议。**置信度：medium**。

## Sound · medium：保留历史类型债，拒绝一次性关闭 noCheck

- **时间**：本轮范围确认。
- **选择与场景**：测试全绿，但初始宿主强制类型检查产生 1407 条诊断。若直接删除 `noCheck`，会把这次运行缺陷修复变成全仓类型迁移；若用 any 或忽略注释压下错误，又会伪造安全感。本轮保留现状并在贡献指南披露。
- **未指定处**：“优化质量”是否要求本轮迁移全部宿主类型。
- **影响**：Node 22 构建与运行测试仍是当前门槛；它们不证明宿主类型安全。新增的公共 HTTP 原语单独通过严格类型检查。后续应按依赖边界补会话、额度和模型契约，再启用检查。
- **判断**：sound。范围可验证，验证结论不夸大。**置信度：medium**。

## Sound · high：登录代次与凭据版本分开

- **时间**：本轮账号存储修复。
- **选择与场景**：用户注销后用完全相同的 token 再登录。只比较 token 会把新旧登录认成同一个；因此每次主动保存登录都生成新的代次，正常刷新保留它。写回前再比较代次和 token / 过期时间组成的版本；不一致就拒绝旧结果。
- **未指定处**：如何识别“值相同但已不是原登录”的账号。
- **影响**：现有 auth.json 的 vault 新增 generations 元数据，不另建凭据文件。旧文件可读取并得到稳定代次，后续写入保存它；代次不是厂商会话 / 缓存 ID，绝不写到厂商请求里。
- **判断**：sound。覆盖同凭据重新登录，而不只覆盖测试里 token 不同的样本。**置信度：high**。

## Sound · high：额度与身份补全只合并自身改变的字段

- **时间**：本轮存储消费者迁移。
- **选择与场景**：同一账号的额度查询更新套餐，身份查询更新邮箱。如果二者把旧账号整份覆盖回去，后返回者会抹掉先返回者的新字段。因此先校验来源登录与凭据，再只合并相对来源快照发生变化的字段；身份重命名也不覆盖已占用该名字的另一登录。
- **未指定处**：多个异步补全的结果如何合并。
- **影响**：聊天刷新、额度 hydration 和验证提示必须走同一条件写回机制；不能绕开它用普通 saveSession 保存迟到结果。相同字段并发变化仍以最后被接受的写入为准。
- **判断**：sound。避免为了修注销竞态而引入并发 metadata 丢失。**置信度：high**。

## Sound · high：厂商 transport 归厂商，公共 HTTP 工具不懂厂商

- **时间**：本轮项目树整理。
- **选择与场景**：Kiro 的异常帧或 Cursor 的 HTTP/2 行为要修改时，维护者进入该家的 transport，而不是在巨型 proxy 中搜索另一家的实现。共同的 JSON HTTP 回复与错误描述放在 utils；缓存、请求头和帧协议仍各自独立。
- **未指定处**：按文件行数拆分，还是按行为所有者拆分。
- **影响**：新增转换型厂商应延续家族拥有整个 wire 生命周期的边界。没有建立万能厂商适配器，也没有改变 DSH 的协议选择或上游身份。
- **判断**：sound。边界能解释哪些变更应该一起发生，而不只是减少一个文件的行数。**置信度：high**。

## Sound · high：停止工作与错误结束不能伪装为成功

- **时间**：本轮流处理修复。
- **选择与场景**：Kiro 输出半句后收到异常，客户端得到 error 事件而非 stop/DONE；还未输出时则直接得到错误 HTTP 状态。非法帧长立即失败，EOF 有残帧也失败。Cursor 取消时真正销毁该请求独占的连接；等待下游写完再读取下一块，而不是排队无限多个写入任务。
- **未指定处**：错误应变成可见文本、成功终帧，还是失败；慢客户端是否允许上游继续无限生产。
- **影响**：部分成功文本不会被抹掉，但不能宣称完整答复成功；不在已输出后偷偷重试制造重复文本。保留现有 Kiro 帧长上限，不额外设定未经证据支持的 Cursor Run deadline。
- **判断**：sound。错误、取消与正常完成保持不同含义，工作量随背压受限。**置信度：high**。

测试方法采用临时合成凭据、loopback HTTP/2 和 mock 厂商响应；未作真实厂商登录或线上聊天验收。内部命名、格式、回归文件位置等局部选择合并记为一项常规实现裁量。

## 复审修正与其余边界

- **一次性连接与严格串行消费（sound · medium，本轮传输实现）**：正常终帧也销毁该请求独占的 HTTP/2 连接，不预留连接复用或继续读取 trailer。慢消费者会连同后面的 KV / exec 控制消息一起延迟；没有额外拆分有界控制队列。选择保序和简单生命周期，未来若复用连接必须重新定义所有权。
- **不是完整协议校验器（sound · medium，本轮范围）**：Kiro 检查已有帧长上限、header 区域与 EOF，但不新增 CRC 或所有内部 header/JSON 校验；一次 feed 中后帧出错时，前帧尚未返回也会一起失败。parser.finish 只校验 EOF，生产调用在错误后销毁 reader，不尝试在坏帧后猜测恢复。Cursor 现已补 Connect 残帧 EOF 校验。
- **取消原因保持一致（sound · high，复审修正）**：预取消和运行中取消都保留同一 signal.reason；不能仅因取消发生得晚，就把原错误替换成笼统的 aborted。

- **差量必须包含删除（sound · high，本轮复审修正）**：验证成功会移除旧警告字段，只遍历新对象的字段会遗漏删除。Codex 指出该回归后，以真实 Controller 额度刷新补测；差量按来源与新值的字段并集计算，不删除来源从未见过的并发新增字段。这是完整差量语义，不是 Antigravity 专用补丁。
- **重名身份不合并（needs-user · low，本轮重键防护）**：两个登录后来被识别成同一邮箱时，保留各自凭据与旧存储 key，可能有同名卡片。暂保留以防无声丢号；未来可加用户主动合并，而不是用显示邮箱替用户选 token。
- **不主动撤销已发出的请求（sound · medium，本轮范围）**：注销使旧写回失效，但不取消已经发到厂商的 HTTP 请求。若产品要求退出立即停止计费，需要单独的请求撤销机制。
- **模型保存仍用原顺序（sound · medium，本轮范围）**：先改内存，再写磁盘，再同步宿主；失败会报错，但本轮未新增回滚、多写者锁或降级往返协议。用新对象重新读盘的测试不等同于真实 GUI 重启验收。
- **存储直接依赖与来源句柄（sound · medium，本轮刷新实现）**：TokenManager 直接使用唯一 store，移除无账号概念的 load/save/remove 注入。remember 用 WeakMap 绑定返回的原 session 对象；未来若 clone 后调用须改成显式账号句柄，不能假定仍可写回。资料补全来源已失效时跳过，后续查询自行恢复；无关资料不计入凭据版本。
- **未复现的登录尾段风险（scope · medium，本轮未实施）**：device 登录的后续身份查询和 import/auto-import 并未全面纳入本轮刷新所有者。注销与迟到登录结果的 claim 校验、Cursor skipped import 是否还应保存，以及旧刷新未删除当前账号却仍提示重新登录的文案，均留待有回归证据的独立小任务；本轮不宣称所有 OAuth 竞态已消除。
- **单次使用 token 的外部副作用（sound · medium，保护优先）**：旧刷新已消耗厂商 token 后，用户又导入相同旧凭据，不能通过回滚本地文件撤销厂商轮换。当前拒绝把旧结果转交给新登录，不自动切到另一账号；若未来接纳同一凭据链的结果，需要额外身份证明。
